# My Spatial Refuge (myspatialrefuge) — 配置/数据/升级体系 + 多版本布局

事实来自逐文件阅读；标「推断」为无直接证据的推理。

## 1. 核心框架

`00_MSR.lua` 经 `getModInfoByID("myspatialrefuge")` 建全局 `MSR`（VERSION / GAME_VERSION / _loaded / _modules）。**模块注册模式**：`MSR.register(name)` 若已加载则返回 nil，各文件写 `local X = MSR.register("Foo"); if not X then return MSR.Foo end` → 幂等防重载。加载序 KahluaCompat→Logging→Env→Config→Data→Utils→Difficulty→Events→Validate（启动自检 8 项 → `MSR._coreValid`）。注意 `Transaction`/`InventoryAuthority`/`Validation`/`UpgradeData` **不走 register**，直接赋值 `MSR.X`。全局别名：**K**=KahluaCompat（补 Kahlua 缺失的 `next()`/`os.*`：isEmpty/count/keys/iter/size/toTable/time/safeCall，Java ArrayList 0 基迭代）；**L**=Logging（`L.logger(tag)`→debug/info/warning/error，写 `MySpatialRefuge` 日志，控制台 `[CLIENT|SERVER|SHARED][MSR:Tag]`）；**D**=Difficulty（core/material/cooldown/positiveEffect/positiveValue/negativeEffect/negativeValue；`SandboxVars.MySpatialRefuge.Difficulty` 1–5 → coreCost 与 cooldown=0.5/0.75/1/1.5/2，effectPower=1.2/1.1/1/0.9/0.8；**D.material = D.core，二者当前完全等价**）。调试：`L.isDebug()`（缓存 `getDebug()`，即 Options>Display>Debug）门控 `L.debug`；`Env.isDebugEnabled()` 兼容三种 API，同时门控 `debugOnly` 升级。`Env` 缓存判定 SP=(false,false) / server=(true,false) / client=(false,true)，注释明确 (true,true) 不出现（coop 也是双进程）；canModifyData=hasServerAuthority=SP 或 server，needsClientSync=isServer。`Events` = OnServerReady/OnClientReady/OnAnyReady + Custom 本地发布订阅 + Server 客户端→服务端桥。

## 3. upgrades.yaml 与解析链

顶层仅两个 key（无 version/schema）：`itemGroups`（12 组：skillbooks_1..5 各 24 本、wristwatches、alarm_clocks、vehicle_tires、medical/bedding/entertainment/pain_relief 的 tier1/2）与 `upgrades`（11 条 / 43 级）。条目字段：id、name(翻译键)、icon、category(comfort 5 / general 3 / shelter 2 / ecology 1)、maxLevel、dependencies、levels；level = {description, effects, requirements}，requirement = {type, count, substitutes}。**dependencies 只有 `refuge_basement→["expand_refuge"]` 非空**，其余为空——前置分两层：dependencies（依赖升级须满级，`isUpgradeUnlocked`）+ 逐级 requirements（物品）。substitutes 用自研 `$组名`（`*` 亦可、`$组+A` 追加）替代 YAML 锚点。effects 共 10 键：readingSpeedMultiplier、refugeCastTimeMultiplier、relicStorageCapacity、refuge{Wound,SleepFatigue,Mental,Stiffness}RecoveryMultiplier（各 5）、corePickupRadius、refugeCropGrowthTimeMultiplier（各 3）、vehicleTeleportEnabled（1）。

解析：`CUI_YamlParser.parseFile("myspatialrefuge","media/lua/shared/upgrades.yaml",{expandGroups=true,groupsKey="itemGroups",refPrefixes={"$","*"}})`；`CUI_FileUtils.readModFile` 先 `resolveModId`（依次试 `modId` 与 `\modId`）——因为 mod 不存在时 `getModFileReader` 抛 **pcall 抓不住的 Java NPE**——再 `getModFileReader(id,path,false)` 逐行 readLine，失败统一返回 nil 且**无跨目录自动回退**；路径不拼 `common/`，由引擎解析（推断：引擎在 common/ 与版本目录中查找）。parser 是手写缩进解析器：支持整行/行内 `#` 注释（引号内除外）、嵌套 map 与 `- ` 列表、`- k: v`、行内 `[]`/`{}`、引号、true/yes/on、null、tonumber；**不支持锚点/别名、多行字符串 `|`/`>`、多文档**；全程 pcall 从不抛异常（失败→`{}`），**所有 key 都是字符串**（故 `levels["1"]`，读取处用 `levels[l] or levels[tostring(l)]`），未知行静默跳过。

`MSR.UpgradeData`：先载 Lua `UPGRADE_DEFINITIONS`（`expand_refuge` maxLevel 8、cores 与 TIERS 对齐；`debug_fail_upgrade` 带 debugOnly），再 YAML **同名覆盖**，落 `_upgrades[id]` 与 `_categories[cat]`（有序 id 数组）→ 运行时共 13 条 / 52 级。等级存 `refugeData.upgrades`（**按避难所而非玩家**，注释称便于将来 coop），EXPAND_REFUGE 特判为 `refugeData.tier`；等级变化时 `UpgradeEvents.OnLevelChanged.Fire`。

消耗与校验链：`purchaseUpgrade` → `canPurchaseUpgrade`（有 refugeData、升级存在、debugOnly 需调试、依赖满级、只能 +1 且不超 maxLevel、材料可满足）→ `Transaction.Begin` 锁材料 → `executeAuthoritative`：handler.validate → `validateAllocationForRequirements`（**最大流**判定多 requirement 与 substitutes 的匹配，不依赖配方顺序）→ `InventoryAuthority.consumeWithReceipt` 按 itemId 原子扣除并留 receipt → handler.commit / `setPlayerUpgradeLevel` → 失败 refundReceipt、成功 finalizeReceipt → reconcile 或 applyUpgradeEffects。难度缩放唯一入口是 `getNextLevelRequirements`：CORE_ITEM 走 `D.core`、其余走 `D.material`（保留 substitutes）；`getLevelEffects` 返回纯 `{效果名=值}` 平表且**不缩放**；`getPlayerActiveEffects` 按白名单聚合（max / min / add，**仅 min 类吃 `D.positiveEffect`**，max/add 不吃 effectPower）。

## 4. MSR_Transaction.lua 的机制与保护目标

不用 register，直接建表；状态 PENDING / COMMITTED(SP 本地已扣) / FINALIZED(MP 服务端已扣、本地清锁) / ROLLED_BACK。机制是**分配清单（journal）式两阶段锁定**，不做世界快照：锁就是 itemId 列表，存 `activeTransactions[username][type]` 与玩家 ModData `_lockedTransactionItems`（跨重连存活）。`Begin` 拒绝已有未过期事务、把 `$substitutes` 解析成 type→count 后逐个 `lockItems`（任一不足即回滚已锁部分）；`Commit` 精确扣除、`Finalize` 仅清锁、`Rollback` 只解锁；三者与 `Begin` 均以 `status==PENDING` 为门，重复调用只返回 false → 即幂等防重放。事务 ID=`username_type_时间戳_计数`。超时是**硬编码 `TIMEOUT_SECONDS=5`**，由 `Events.EveryTenSeconds` 批量检查（跳过 dedicated）自动回滚并 `PM.Say(ACTION_TIMEOUT_ITEMS_UNLOCKED)`；另有开局清陈锁与 `ForceCleanup`。它用原版 PZ Events 而非 MSR.Events 包装。保护目标：①**不复制**——锁定期物品不被其他系统取用；②**不丢失**——receipt 逆序回填「原容器→玩家背包→脚下地面 AddWorldInventoryItem」；③**MP 权威**——客户端只发 transactionId+lockedItemIds，扣物只发生在服务端进程；④**不留半完成**——超时/失败一律回滚，避免永久锁死。已知缺口：计数快路径 `GetMultiSourceCount` 不排除装备/收藏，UI 可用数可能虚高；`OnPlayerDisconnect` 实际只挂了 OnPlayerDeath，掉线仅靠 5 秒超时回收。

## 5. EffectSystem / EffectRegistry / EffectProvider

`EffectProvider.create{sourceName,calculateEffects,shouldApply,onEffectsChanged,priority}` 只是契约工厂（不 tick、不写玩家属性）；`registerEffects` 先 `unregister(source)` 再逐条注册 = **全量覆盖语义**。`EffectRegistry` 按玩家（`getOnlineID` 优先，退化 username）存 `效果名→{sources[],total,stackingRule}`，同 source 覆盖、多来源按 ADDITIVE/MAXIMUM 合并，`get` 时 dirty 才重算；OnLoad / OnPlayerDeath 清缓存。`EffectSystem` 编排：`updatePlayer` = 未脏直接返回 → clear → 逐 provider registerEffects → recalculate；另有 markDirty/getEffect/getAll。

**内置效果仅 4 个**（全部 MAXIMUM、默认 1.0）：`refugeWoundRecoveryMultiplier`、`refugeSleepFatigueMultiplier`、`refugeMentalRecoveryMultiplier`、`refugeStiffnessRecoveryMultiplier`，唯一消费者是客户端 `MSR_RestorationEffects.lua`，节拍来自它挂的 `Events.EveryOneMinute`（**EffectSystem 自身不 tick**，只挂 OnLoad）。唯一内置 provider 是 `MSR_UpgradeEffects`（sourceName="UpgradeEffects"），把 `getPlayerActiveEffects` 中命中这 4 个名字的转成 effect；其余升级效果（readingSpeedMultiplier、refugeCastTimeMultiplier、relicStorageCapacity、corePickupRadius）**绕过 EffectRegistry**，直接读 `getPlayerActiveEffects`（MSR_ReadingSpeed 钩 `ISReadABook.getDuration`、MSR_Cast、Config.getRelicStorageCapacity、MSR_AutomaticCorePickup）。`MSR_UpgradeEvents` 是自建事件总线，仅 `OnLevelChanged.Add/Remove/Fire`（等级持久化后逐 handler pcall）。死代码：`priority` 存而不用、`onEffectsChanged` 与 `updateAllPlayers` 无调用点。

## 6. 物品与实体脚本

- `items_ZombieCore.txt`：`module Base / item MagicalCore`，ItemType=base:normal、Weight 0.02、Icon=ZombieCore、StaticModel/WorldStaticModel=Clay，**无 Tags**。掉落由 `server/ZombieCoreDrops.lua`：读 `SandboxVars.MySpatialCore.ZombieCoreDropChance`（默认 30，clamp 1–100），`OnZombieCreate` 里 ZombRand 判定 + `addItemToSpawnAtDeath`，仅 server 注册。
- `items/msr_experience_essence.txt`：`MSR_ExperienceEssence`，base:normal、0.1、Icon=ExperienceEssence、Tooltip=Tooltip_MSR_ExperienceEssence。
- `items/sru_virtual_items.txt`：14 个 `SRU_` 占位物（SkillBookTier1–5、Medical1–2、Bedding1–2、Entertainment1–2、PainRelief1–2），一律 ItemType=base:literature、Weight 0.1、图标借 vanilla（Book8/Bandage/Pills/Sheet/…），**无 Tags、无世界模型、无 loot 分发**。物品系统对它们**无任何特殊分支**：它们只是 yaml 里 `requirements.type` 的锚点（自身可用数恒 0），实际消耗靠 `$skillbooks_N` 等 substitutes 展开的真实书籍履约。
- `entities_spatial_well.txt`：`entity MSRSpatialWell`（= Config.SPATIAL_WELL.ENTITY_SCRIPT）。UiConfig{xuiSkin=default, entityStyle=ES_Well, uiEnabled=false}；FluidContainer{ContainerName=Well, Capacity=400.0, FillsWithCleanWater=true, InitialPercentMin/Max=0.1, InputLocked=true, Fluids{Water:1.0}, whitelist{Water}}（0.1×400=40 即 INITIAL_WATER）；SpriteConfig face S layer row=`myspatialrefuge_1`。`MSR_SpatialWell`（register 名 "SpatialWell"、事务类型 SPATIAL_WELL_BUILD）提供放置/移动/补水/查找/防破坏 API；**取水不在 Lua 里**，交给 B42 实体流体容器。持久化双轨：世界 IsoThumpable + ModData 标记（isSpatialWell/refugeId/spatialWellSprite、血量 999999、不可拆），水量存实体 FluidContainer；坐标与 placed 存 `refugeData.customizations.spatialWell` 经 `Data.SaveRefugeData` 落盘。校验自实现（isSquareFree + `Data.GetRefugeDataAtPosition`），不直接引用 MSR_Validation，物品侧经 Transaction → InventoryAuthority。隐患：`EnsureForRefuge` 物体丢失重建时水量退回 40。

## 8. 目录布局

`common/` 放全部代码与资源（lua shared/client/server、scripts、textures、ui、texturepacks、`myspatialrefuge.tiles`、`sandbox-options.txt`）；**42.14/ 与 42.15/ 只放 `mod.info` + icon/poster + `Translate/`（EN/CN/ES/PTBR/RU）**，即版本目录只承载随游戏版本变化的部分。两份 mod.info 的 id/name/modversion 相同（1.27.1）：42.14 用 `versionMin=42.14` + `versionMax=42.14`（锁死该版本），42.15 只有 `versionMin=42.15`（向上开放）；`pack=myspatialrefuge` 指向 `media/texturepacks/myspatialrefuge.pack`（引擎读打包纹理而非散图）；`tiledef=myspatialrefuge <起点>` 42.14=**13232**、42.15=**5933**，两版各一套起始编号以免撞上各版本 vanilla 已占 tile（推断：起点必须落在该版本空闲区间）。`.tiles`（329B 二进制）内含 `myspatialrefuge_0/1` 与 BlocksPlacement/ContainerCapacity/CustomItem/PhysicsShape/ScrapUseSkill 等属性串，是 SACRED_RELIC / SPATIAL_WELL 与实体 SpriteConfig 的落点。翻译格式：42.14 为 `.txt` Lua 表 `ItemName_CN = { ["Base.MagicalCore"] = "奇异核心" }`（按 5 个命名空间 ItemName/Sandbox/Tooltip/UI/IG_UI + 语言后缀分文件）；42.15 为 `.json` 扁平对象 `{"Base.MagicalCore": "奇异核心"}`（文件名去掉语言后缀）。两版命名空间集合一致。`texturepacks/myspatialrefuge.txt`：version=0、packFileName=myspatialrefuge.pack、outputImageSize=1024,1024、scale50=false、两条 inputImageDirectory（`../` 非 tilesheet；`2x/` imagesAreTilesheets=true）、tileDef path=myspatialrefuge.tiles。
