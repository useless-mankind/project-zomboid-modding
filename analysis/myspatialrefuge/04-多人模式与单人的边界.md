# 04 · 多人模式与单人的边界

> 目的：**只做单人开发时，哪些代码必须读、哪些可以直接跳过、哪些碰不得。**
> 证据标记：`[文件]` = 源码原文属实（附 `文件:行号`）；`[推断]` = 由代码结构推出、未经运行时确认。
> 路径均相对于 `mods/myspatialrefuge/`。

---

## 0. 一句话结论

**SP 与 MP 是两条完全独立的代码路径**，自定义命令协议（`sendClientCommand` / `OnClientCommand` / `OnServerCommand`）是 **MP 专属，单机一行都不走**。

**但是——`media/lua/server/` 不是"多人模式目录"，删掉它会立刻弄坏单机。** 见第 2 节的三条证据。

> 结论：只做单人时，正确姿势是**跳过不读**，不是**删除**。

---

## 1. 两条路径总览

```
玩家点「进入避难所」
│
├─ SP 路径（isMultiplayerClient() == false）
│   MSR.EnterRefuge                    client/MSR_Teleport.lua
│   └─ MSR.GenerateNewRefuge（首次）→ doSingleplayerEnter（本地分步传送）
│
└─ MP 路径（isMultiplayerClient() == true）
    sendClientCommand(RequestEnter)  ──网络──▶  OnClientCommand 分发（server/MSR_Server.lua:929）
                                                └─ HandleEnterRequest → sendServerCommand(TeleportTo)
    OnServerCommand 路由（client/MSR_ServerCommandRouter.lua:320）◀──网络──┘
    └─ handleTeleportTo → teleportTo → 等区块 → sendClientCommand(ChunksReady) → …
```

**统一模式**：每一处 MP 分支都是同一个形状 —— `if <有本地权威> then <直接本地执行> else <发命令给服务端> end`。所以**读懂单机，只要读 `if` 的"真"分支**。

---

## 2. 决定性证据：`server/` 目录在单机也在跑

### 证据 1 — 代码自己写的守卫只在单机下成立

```lua
-- server/ZombieCoreDrops.lua:42
if isServer() or not isClient() then
    Events.OnZombieCreate.Add(onZombieCreate)
end
```

单机下 `isServer() == false`、`isClient() == false` → `not isClient()` 为真 → **注册生效**。这个判断只有在"server 目录会被单机加载"的前提下才有意义。

### 证据 2 — 单机的 `/msr` 直接依赖 server 目录里的模块（最硬）

```lua
-- client/MSR_SlashCommands.lua:202-207
if not MSR.AdminHandler or not MSR.AdminHandler.Execute then ...
local ok, response = pcall(MSR.AdminHandler.Execute, player, payload)
```
而 `MSR.AdminHandler` 定义在 **`server/MSR_AdminHandler.lua:10`**。

> **删掉 `media/lua/server/` → 单机的 `/msr` 立刻报废。**

### 证据 3 — 一批单机核心机制就注册在 server 文件里

| 机制 | 位置 | 在单机是否生效 |
|:---|:---|:---|
| 僵尸掉核心 | `server/ZombieCoreDrops.lua:43` | ✅（见证据 1） |
| 核心自动拾取 | `server/MSR_AutomaticCorePickup.lua:401-402`（无条件注册） | ✅ |
| 水井补水 | `server/MSR_SpatialWellServer.lua:186-189`（`OnServerReady` + `EveryTenMinutes`） | ✅（SP 会触发 `OnServerReady`，见 §7） |
| 肥沃共鸣（作物加速） | `server/MSR_FertileResonance.lua:152` | ✅ |
| 避难所衰减回收 | `server/MSR_Decay.lua`（无事件，由 `Data` 分配槽位时调用） | ✅ |

## 6. 单机路径图纸（5 条主链）

| 玩法 | 单机调用链 |
|:---|:---|
| **进入避难所** | `MSR_RadialMenu`（轮盘项）→ `MSR.BeginTeleportCast` → `ISTimedActionQueue`（`ISEnterRefugeAction`，时长受 `faster_refuge_cast` 升级缩放）→ `MSR.EnterRefuge` → 首次则 `MSR.GenerateNewRefuge` → `doSingleplayerEnter`（分步轮询传送，`MSR_Teleport.lua:54`） |
| **退出避难所** | `MSR.ExitRefuge` → `doSingleplayerExit`（`:121`，先存 roomIds 再传送回原坐标） |
| **升级** | `UpgradeLogic.purchaseUpgrade` → `purchaseUpgradeSP`（`MSR_UpgradeLogic.lua:415`）：`Transaction.Begin`（锁料）→ `executeAuthoritative` → 失败 `Rollback` / 成功 `Finalize` → `onUpgradeComplete`。**全程本地，不跨进程** |
| **放水井** | `MSR.SpatialWell`：`hasServerAuthority()` 为真 → 本地放置 + `Data.SaveRefugeData` 存盘 |
| **吸收经验精粹** | `XPR.DoAbsorb`（`MSR_XPRetention.lua:558`）：`ensureAuthority()` 为真 → 本地直接 `XPR.HandleAbsorbRequest`（:565） |

> 对照：MP 下同一入口在 `:229` / `:277` / `:408` / `:546` / `:573` 分叉去发命令。**单机实现是完整独立的一套，不是走命令协议的本地回环。**

## 7. 单机下"看似服务端、实际是主干"的机制（别删）

| 机制 | 为什么单机也在用 |
|:---|:---|
| `MSR.Events.OnServerReady` | 单机**会触发**（`Events.lua:75`：`hasServerAuthority()` 为真即触发）。水井补水、肥沃共鸣安装、升级处理器注册（`MSR_UpgradeLogic.lua:753`）、自动拾取初始化都挂在这上面 |
| `MSR.Transaction` + `MSR_InventoryAuthority` | 单机升级 / 水井照样走事务锁料与权威扣料，防止物品复制与丢失 |
| `Data.CanModifyData()` | 单机恒为 true，是写存档的总开关 |
| `MSR.Events.Server.Register/Fire` | 名字带 Server，但单机下走的是本地直通路径；只有 MP 才真的跨进程 |
| `MSR_AdminHandler` / `MSR_AdminCommands` | 单机 `/msr` 直接调用（见证据 2） |

## 8. 将来真要瘦身时的最小安全切口

如果哪天想彻底删掉 MP 代码（**不建议**，你只自用，读的时候跳过即可），最小切口是：

**可以安全删**
1. `client/MSR_ServerCommandRouter.lua`（整文件）
2. `server/MSR_Server.lua` 的 `OnClientCommand` 分发器 + 8 个 `Handle*Request`
3. `Config.COMMANDS` 整段
4. `Events.lua` 的 `MSR_ServerEvent` 桥（:316-317, 480, 520, 554, 557）
5. `Data.lua` 的 ModData 同步段（:103, 113-152）

**删前必须逐个确认调用方**
1. `MSR.AdminHandler.Execute` —— 单机 `/msr` 在用（**最容易误删**）
2. `MSR_Server.GetRelicContainer` —— 被 `shared/MSR_Transaction.lua:100` 作为回退引用
3. `MSR_Server.InvalidateRelicContainerCacheForUser` / `CheckAndRecoverStrandedPlayer` —— 需确认无单机调用方
4. 所有 `hasServerAuthority()` 门 —— 单机全部为真，删掉判断会改变单机行为

## 9. 只做单人时的阅读/改动建议

**每次改动前必读（主干）**

```
shared/00_core/{00_MSR, Config, Data, Env, Events, Utils, Difficulty}.lua
shared/{MSR_UpgradeData, MSR_UpgradeLogic, MSR_Transaction, MSR_InventoryAuthority}.lua
shared/{MSR_RefugeGeometry, MSR_RefugeGeneration, MSR_Integrity, MSR_BoundaryReconciler}.lua

client/MSR_Main.lua  client/MSR_Teleport.lua  client/MSR_RadialMenu.lua  client/MSR_Context.lua
server/MSR_AdminCommands.lua   ← 单机 /msr 实现
```

**可以直接跳过**

```
client/MSR_ServerCommandRouter.lua      ← 整文件
server/MSR_Server.lua:925-992           ← 分发器
server/MSR_AdminHandler.lua:148         ← OnClientCommand 注册（Execute 本身要读）
所有 sendClientCommand / sendServerCommand 调用点
shared/00_core/Events.lua 的 ServerEvent 桥（:316-317, 480-530, 554-557）
```

**碰不得**

```
media/lua/server/ 整个目录 —— 单机在跑（见第 2 节）
hasServerAuthority() 判断 —— 单机恒真
Data.CanModifyData() —— 单机写存档总开关
MSR.AdminHandler / MSR.AdminCommands —— 单机 /msr 依赖
```
